# Migrate to domain.md 1.0.0-rc.3

Specification `1.0.0-rc.3` generalizes the constitutional model introduced in rc.2. Package and
specification versions remain independent; the unreleased package carrying this contract is `0.3.0`.

The vocabulary dependency is the IXO constitutional-subject module merged at
`ixofoundation/ns@c9557bf0b8b7bc842501ba132e90e3edee0739ba`:

- `https://w3id.org/ixo/vocab/v1/constitution#`
- `https://w3id.org/ixo/vocab/v1/constitution/subjects`
- `https://w3id.org/ixo/context/v1`

## Why rc.3

A constitutional subject is a semantic role, not a synonym for a legal entity. The subject may be a
person, organisation, asset, commodity, financial instrument, property right, agreement, deed, project,
work, protocol, service, oracle, claim, credential, evidence item, decision, outcome, place, biological
subject, network, or agentic twin. Multiple classifications may apply to the same subject.

`domain.type` remains a coarse serialization and manifest-selection category. It does not replace the
subject taxonomy, constitutional archetypes, constitution type, or instrument classification.

## Required migration from rc.2

1. Change `version`, `conformance.spec_version`, and the schema URN to `1.0.0-rc.3`.
2. Add `constitution.subject_profile`, including every field defined by the rc.3 schema.
3. Put at least one vocabulary IRI in `subject_types`. Use multiple types when the subject crosses
   categories, such as a forest that is both a natural asset and biological subject.
4. Put the canonical `constitution.subject` identifier in `subject_profile.identity`.
5. Select zero or more non-exclusive archetypes: `Stewarded`, `Owned`, `Managed`, `Governed`,
   `Regulated`, `Verified`, and `Settled`.
6. Reference the subject's purposes, interests, values, rights, obligations, capabilities, claims,
   wallets, authorities, memory, evidence/evaluation/decision/settlement policies, governance, actors,
   oracles, and agentic twins. Use empty arrays only when a facet is genuinely absent.
7. Resolve bare local references to declared documents, resources, rights, services, controllers,
   agents, or linked entities. Runtime consumers must resolve external IRIs, DIDs, CIDs, and compact IRIs.
8. Include every declared agentic twin in `constitutional_ai.applies_to_agents`. A twin is a distinct,
   recursively constitutional subject and does not inherit live authority from its parent.
9. Re-render pinned protocol templates so their generated draft identifier is propagated through the
   subject profile and every exact subject reference.
10. Run the rc.3 `domainmd lint` lane and obtain the controller approval required for constitutional,
    authority, rights, execution, or policy changes.

## Operational boundary

The authoring and runtime sequence is:

`Identity → Constitution → Claims → Evidence → Evaluation → Decision → Capability → Action → Settlement → Memory`.

This sequence does not self-authorize transitions. Before an action, resolve current protocol state,
IID/controller state, rights, capabilities, approvals, revocation, effective instruments, and enforcement
state. Constitutional-AI critique or policy evaluation constrains a proposal; it does not supply identity,
capability, approval, or execution authority.

There is no automatic migration for anchored or runtime domains. The profile changes constitutional
meaning and therefore requires review and an auditable amendment or adoption decision under the domain's
current authority.
